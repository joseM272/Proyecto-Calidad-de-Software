Fundamentos de Calidad

La calidad de software es uno de los aspectos fundamentales dentro de la Ingeniería de Software. No se refiere únicamente a que un programa funcione o que no tenga errores, sino a que el producto desarrollado cumpla con los requisitos establecidos, satisfaga las necesidades de los usuarios y pueda mantenerse y evolucionar de manera adecuada. A medida que los sistemas de software se vuelven más complejos y tienen una mayor importancia en áreas como la banca, la salud, la educación, el comercio y la industria, la calidad adquiere una importancia cada vez mayor. Un sistema de mala calidad puede generar pérdidas económicas, problemas de seguridad, pérdida de información, insatisfacción de los usuarios e incluso consecuencias graves cuando se utiliza en sistemas críticos. Por este motivo, la calidad debe considerarse durante todo el ciclo de vida del software, desde la definición de los requisitos hasta el mantenimiento del sistema.

Software Quality Assurance

La calidad es el grado en que un sistema cumple con los requisitos definidos, satisface las necesidades de los usuarios y funciona de manera confiable durante su ciclo de vida.

¿Qué significa que un software sea de calidad?

Un software de calidad no significa solamente que “funcione”. También debe ser:

  • Correcto: hace lo que se especificó.
  • Confiable: funciona de manera consistente y sin fallos frecuentes.
  • Seguro: protege los datos y evita accesos no autorizados.
  • Eficiente: utiliza adecuadamente recursos como memoria, CPU y red.
  • Usable: es fácil de aprender y utilizar.
  • Mantenible: permite corregir errores y realizar cambios fácilmente.
  • Escalable: puede soportar un aumento de usuarios o datos.
  • Compatible: puede funcionar con otros sistemas y entornos.

Calidad vs. pruebas

Es importante distinguir estos conceptos:

Aseguramiento de la calidad (QA)

Busca prevenir defectos y mejorar los procesos utilizados para desarrollar software.

Control de calidad (QC)

Busca detectar defectos en el producto mediante revisiones, pruebas y otras técnicas.

Testing o pruebas

Consiste en ejecutar o analizar el software para encontrar comportamientos incorrectos.

QA → definir buenas prácticas y procesos.
QC → verificar que el producto cumpla los criterios establecidos.
Testing → ejecutar casos de prueba para descubrir errores.

Principales atributos de calidad

Un modelo muy utilizado es ISO/IEC 25010, que organiza la calidad del producto software en las siguientes características:

Adecuación funcional
¿Hace correctamente lo que debe hacer?
Eficiencia de desempeño
¿Utiliza bien los recursos y responde rápidamente?
Compatibilidad
¿Puede coexistir e interactuar con otros sistemas?
Usabilidad
¿Es fácil de aprender y utilizar?
Fiabilidad
¿Funciona correctamente durante el tiempo esperado?
Seguridad
¿Protege la información y los accesos?
Mantenibilidad
¿Es fácil modificar, corregir y mantener?
Portabilidad
¿Puede trasladarse a otros entornos?

Prevención de defectos

Un principio fundamental es que es más barato prevenir un error que corregirlo cuando ya llegó al usuario.

Por eso se utilizan prácticas como:

  • Revisiones de código.
  • Análisis estático.
  • Pruebas unitarias.
  • Pruebas de integración.
  • Integración continua.
  • Automatización de pruebas.
  • Revisiones de requisitos.
  • Control de versión.
  • Estándares de programación.

Niveles de pruebas

Las pruebas suelen organizarse en diferentes niveles:

  • Pruebas unitarias: verifican componentes pequeños, como funciones o clases.
  • Pruebas de integración: verifican que varios componentes funcionen correctamente juntos.
  • Pruebas de sistema: evalúan el sistema completo.
  • Pruebas de aceptación: comprueban que el software satisface las necesidades del cliente o usuario.

Un concepto clave: la calidad no es ausencia de errores

Un programa puede tener pocos errores y aun así ser de mala calidad.

Por ejemplo, una aplicación bancaria podría funcionar técnicamente sin errores, pero si tarda 30 segundos en mostrar cada pantalla o tiene una interfaz confusa, la calidad percibida será baja.

Por eso la calidad debe evaluarse desde diferentes perspectivas:

Requisitos + funcionamiento + rendimiento + seguridad + experiencia del usuario + mantenibilidad.
