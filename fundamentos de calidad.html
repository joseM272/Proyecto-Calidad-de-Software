Fundamentos de Calidad

La calidad de software es uno de los aspectos fundamentales dentro de la Ingeniería de Software. No se refiere únicamente a que un programa funcione o que no tenga errores, sino a que el producto desarrollado cumpla con los requisitos establecidos, satisfaga las necesidades de los usuarios y pueda mantenerse y evolucionar de manera adecuada. A medida que los sistemas de software se vuelven más complejos y tienen una mayor importancia en áreas como la banca, la salud, la educación, el comercio y la industria, la calidad adquiere una importancia cada vez mayor. Un sistema de mala calidad puede generar pérdidas económicas, problemas de seguridad, pérdida de información, insatisfacción de los usuarios e incluso consecuencias graves cuando se utiliza en sistemas críticos. Por este motivo, la calidad debe considerarse durante todo el ciclo de vida del software, desde la definición de los requisitos hasta el mantenimiento del sistema.

Software Quality Assurance

La calidad es el grado en que un sistema cumple con los requisitos definidos, satisface las necesidades de los usuarios y funciona de manera confiable durante su ciclo de vida.

¿Qué significa que un software sea de calidad?

Un software de calidad no significa solamente que “funcione”. También debe ser:

La correcto es la capacidad del software para producir los resultados esperados y cumplir con los requisitos especificados. Un programa es correcto cuando realiza las operaciones para las cuales fue diseñado de acuerdo con las reglas del negocio y las condiciones establecidas. Para conseguirlo, es necesario que los requisitos estén claramente definidos y que el comportamiento del sistema coincida con ellos. Si una función realiza una operación diferente de la solicitada, existe un problema de correctitud, aunque el programa no se cierre ni presente errores visibles. Ejemplo: en una aplicación bancaria, si un usuario transfiere $50.000 a otra cuenta, el sistema debe debitar ese importe de la cuenta de origen y acreditarlo en la cuenta de destino. Si transfiere una cantidad diferente, el software no está funcionando correctamente.

La confiabilidad, también denominada fiabilidad, es la capacidad del software para funcionar de manera estable y consistente durante un período determinado y bajo condiciones específicas. Un sistema confiable debe minimizar la aparición de fallos y, cuando se produzca un problema, debe poder recuperarse sin perder información importante ni afectar gravemente a los usuarios. La confiabilidad es especialmente importante en sistemas que deben estar disponibles durante muchas horas o que procesan operaciones críticas. Para mejorarla, se utilizan pruebas, mecanismos de recuperación, copias de seguridad, monitoreo y controles que permitan detectar problemas antes de que provoquen consecuencias mayores. Ejemplo: un sistema de turnos médicos debe permitir que los pacientes consulten, reserven y cancelen turnos sin que la información desaparezca o se dupliquen las reservas cuando muchas personas utilizan la aplicación.

La seguridad es la capacidad del software para proteger la información, los recursos y las funcionalidades frente a accesos, modificaciones, pérdidas o acciones no autorizadas. Un software seguro debe garantizar que cada usuario pueda acceder únicamente a la información y las operaciones que le corresponden. También debe proteger los datos personales y evitar que personas externas puedan aprovechar vulnerabilidades para alterar el funcionamiento del sistema. Entre las medidas de seguridad se encuentran la autenticación, la autorización, el cifrado de datos, la validación de entradas, la gestión segura de sesiones y el registro de actividades relevantes. Ejemplo: en una aplicación bancaria, un usuario debe poder consultar sus propias cuentas, pero no las de otros clientes. Además, las operaciones sensibles deben contar con mecanismos de protección que impidan su ejecución por personas no autorizadas.

La eficiencia es la capacidad del software para realizar sus operaciones utilizando adecuadamente los recursos disponibles, como el procesador, la memoria, el almacenamiento y la conexión de red. Un sistema eficiente responde en tiempos razonables, procesa las solicitudes sin consumir recursos innecesarios y mantiene un rendimiento adecuado incluso cuando aumenta la cantidad de información o de usuarios. La eficiencia no significa únicamente que el programa sea rápido. También implica que utilice los recursos de manera equilibrada y que no provoque un consumo excesivo que afecte a otros procesos. Ejemplo: una tienda online debe mostrar los productos rápidamente y permitir que los clientes realicen compras sin demoras excesivas. Si cada búsqueda tarda 30 segundos y consume demasiada memoria, el sistema presenta problemas de eficiencia.

La usabilidad es la facilidad con la que los usuarios pueden aprender, comprender y utilizar un sistema para alcanzar sus objetivos. Un software usable presenta una interfaz clara, instrucciones comprensibles, opciones organizadas y mensajes que ayudan a interpretar lo que sucede. También debe permitir que los usuarios identifiquen y corrijan errores sin dificultades innecesarias. Una buena usabilidad reduce el tiempo de aprendizaje, evita confusiones y mejora la satisfacción de las personas. Asimismo, debe tener en cuenta la accesibilidad para facilitar el uso por parte de personas con diferentes capacidades. Ejemplo: una aplicación para solicitar turnos médicos debería permitir seleccionar una especialidad, elegir un profesional y confirmar una fecha sin que el usuario tenga que recorrer numerosas pantallas o interpretar mensajes confusos.

La mantenibilidad es la facilidad con la que el software puede analizarse, corregirse, modificarse o ampliarse después de su desarrollo inicial. Con el tiempo, los sistemas necesitan solucionar errores, adaptarse a cambios tecnológicos e incorporar nuevas funcionalidades. Si el código está desorganizado, contiene muchas repeticiones o carece de documentación, realizar estas modificaciones puede resultar difícil, costoso y riesgoso. Para mejorar la mantenibilidad, se utilizan buenas prácticas de programación, una arquitectura organizada, componentes independientes, documentación adecuada y pruebas automatizadas. Ejemplo: una empresa tiene un sistema de facturación y necesita incorporar una nueva forma de pago. Si el código está bien organizado, los desarrolladores podrán agregar esa funcionalidad sin tener que modificar grandes partes del sistema ni provocar errores en las funciones existentes.

La escalabilidad es la capacidad del software para adaptarse al aumento de la cantidad de usuarios, operaciones o datos sin que su rendimiento se deteriore de manera inaceptable. Un sistema escalable puede crecer junto con las necesidades de la organización. Para lograrlo, puede necesitar optimizaciones, una arquitectura adecuada, mejores recursos de infraestructura o la distribución del procesamiento entre varios servidores. La escalabilidad es importante porque una aplicación que funciona correctamente con pocos usuarios puede presentar dificultades cuando recibe miles de solicitudes simultáneas. Ejemplo: una plataforma educativa debe funcionar correctamente cuando se conectan 100 estudiantes, pero también debe estar preparada para soportar a 10.000 estudiantes durante un examen virtual masivo.

La compatibilidad es la capacidad del software para funcionar correctamente junto con otros sistemas, aplicaciones, dispositivos o componentes de su entorno. Un programa suele depender de servicios externos, bases de datos, interfaces de programación (API), sistemas operativos y otras tecnologías. Por eso, debe poder intercambiar información con esos componentes sin provocar conflictos ni perder datos. La compatibilidad también puede implicar que varias aplicaciones compartan recursos o funcionen simultáneamente dentro de un mismo entorno. Ejemplo: una tienda online debe poder comunicarse correctamente con una pasarela de pagos, consultar los productos almacenados en su base de datos y enviar información al sistema de logística para gestionar los pedidos.

Calidad vs. pruebas

Es importante distinguir estos conceptos:

Prevenir

Aseguramiento de la calidad (QA)

Busca prevenir defectos y mejorar los procesos utilizados para desarrollar software.

QA→ definir buenas prácticas y procesos.
Verificar

Control de calidad (QC)

Busca detectar defectos en el producto mediante revisiones, pruebas y otras técnicas.

QC→ verificar que el producto cumpla los criterios establecidos.
Evaluar

Testing o pruebas

Consiste en ejecutar o analizar el software para encontrar comportamientos incorrectos.

Testing→ ejecutar casos de prueba para descubrir errores.

Principales atributos de calidad

Un modelo muy utilizado es ISO/IEC 25010, que organiza la calidad del producto software en las siguientes características:

¿Hace correctamente lo que debe hacer?

¿Utiliza bien los recursos y responde rápidamente?

¿Puede coexistir e interactuar con otros sistemas?

¿Es fácil de aprender y utilizar?

¿Funciona correctamente durante el tiempo esperado?

¿Protege la información y los accesos?

¿Es fácil modificar, corregir y mantener?

¿Puede trasladarse a otros entornos?

Evolución de los estándares de calidad: ISO 9126 → ISO/IEC 25010

Comparación entre el modelo clásico (ISO 9126) y su sucesor moderno (ISO/IEC 25010).

ISO 9126 — Modelo clásico de calidad de software

Publicado en 1991 y revisado en 2001, fue el primer estándar internacional ampliamente adoptado para evaluar la calidad de productos de software. Definía 6 características principales y sus subcaracterísticas.

01

Funcionalidad

Capacidad del software para cumplir las funciones definidas según las necesidades y requisitos del usuario.

02

Confiabilidad

Capacidad del software para mantener su nivel de rendimiento bajo condiciones específicas durante un período determinado.

03

Usabilidad

Facilidad con la que los usuarios pueden aprender, operar y utilizar el sistema para sus objetivos.

04

Eficiencia

Relación entre el nivel de rendimiento del software y los recursos utilizados (tiempo, memoria, CPU).

05

Mantenibilidad

Facilidad para modificar, corregir, adaptar o mejorar el software después de su entrega.

06

Portabilidad

Capacidad del software para ser trasladado de un entorno a otro (sistema operativo, hardware, plataforma).

Limitación principal: No contemplaba explícitamente la seguridad ni la compatibilidad como características independientes, aspectos cruciales en los sistemas modernos.

ISO/IEC 25010 — Modelo moderno SQuaRE

Parte de la familia SQuaRE (Systems and software Quality Requirements and Evaluation), reemplazó a ISO 9126 en 2011. Amplió el modelo a 8 características, incorporando aspectos críticos del software actual.

01

Adecuación funcional

El software hace correctamente lo que debe hacer, cubriendo las funciones y objetivos del usuario.

02

Desempeño y eficiencia

Rendimiento en relación con los recursos utilizados en condiciones establecidas.

03

Compatibilidad NUEVO

Capacidad de coexistir e intercambiar información con otros sistemas o componentes.

04

Usabilidad

Facilidad de aprendizaje, operación y satisfacción del usuario final.

05

Fiabilidad

Funcionamiento correcto y estable durante el tiempo esperado bajo condiciones definidas.

06

Seguridad NUEVO

Protección de la información y los procesos frente a accesos no autorizados o modificaciones maliciosas.

07

Mantenibilidad

Facilidad para modificar, corregir y mejorar el software con eficiencia.

08

Portabilidad

Capacidad de ser transferido a diferentes entornos de hardware o software.

Prevención de defectos

Un principio fundamental es que es más barato prevenir un error que corregirlo cuando ya llegó al usuario.

Por eso se utilizan prácticas como:

  • Revisiones de código.
  • Análisis estático.
  • Pruebas unitarias.
  • Pruebas de integración.
  • Integración continua.
  • Automatización de pruebas.
  • Revisiones de requisitos.
  • Control de versión.
  • Estándares de programación.

Niveles de pruebas

Las pruebas suelen organizarse en diferentes niveles:

  • Pruebas unitarias: verifican componentes pequeños, como funciones o clases.

  • Pruebas de integración: verifican que varios componentes funcionen correctamente juntos.

  • Pruebas de sistema: evalúan el sistema completo.

  • Pruebas de aceptación: comprueban que el software satisface las necesidades del cliente o usuario.

Técnicas de prueba: Caja Negra y Caja Blanca

Según la perspectiva del tester y el acceso al código fuente, las pruebas se clasifican en dos grandes técnicas:

⬛

Caja Negra

Pruebas de Caja Negra

El tester no conoce el código interno. Solo se observan las entradas y salidas del sistema.

  • Partición de equivalencia
  • Análisis de valores límite
  • Pruebas funcionales y de aceptación
  • Pruebas de usabilidad

Ideal para: validar requisitos desde la perspectiva del usuario.

⬜

Caja Blanca

Clic para ver detalles

Pruebas de Caja Blanca

El tester conoce y analiza el código fuente para diseñar pruebas que cubran el máximo de caminos internos.

  • Pruebas unitarias (TDD)
  • Cobertura de sentencias y ramas
  • Análisis estático del código
  • Pruebas de caminos básicos

Ideal para: verificar la lógica interna y la calidad del código.

Un concepto clave: la calidad no es ausencia de errores

Un programa puede tener pocos errores y aun así ser de mala calidad.

Por ejemplo, una aplicación bancaria podría funcionar técnicamente sin errores, pero si tarda 30 segundos en mostrar cada pantalla o tiene una interfaz confusa, la calidad percibida será baja.

Por eso la calidad debe evaluarse desde diferentes perspectivas:

Requisitos + funcionamiento + rendimiento + seguridad + experiencia del usuario + mantenibilidad

Herramientas de Calidad de Software

Conceptos, tipos de herramientas, ejemplos y beneficios para mejorar el desarrollo y la calidad de los sistemas.

1. ¿Qué son las herramientas de calidad de software?

Las herramientas de calidad de software son aplicaciones, técnicas y recursos que se utilizan durante el desarrollo de un sistema para prevenir errores, detectar defectos, verificar el cumplimiento de los requisitos y mejorar la calidad del producto final.

Estas herramientas permiten evaluar tanto el funcionamiento del software como los procesos utilizados para construirlo y mantenerlo. Algunas revisan automáticamente el código, otras ejecutan pruebas para encontrar fallos y otras ayudan a organizar los defectos detectados y realizar un seguimiento de su corrección.

Pueden utilizarse en diferentes etapas del ciclo de vida del software, desde el análisis de requisitos hasta las pruebas, la implementación y el mantenimiento.

Es importante destacar que las herramientas no garantizan por sí solas la calidad de un sistema. Para obtener buenos resultados, deben combinarse con procedimientos adecuados, personal capacitado, requisitos claros y buenas prácticas de desarrollo.

2. Principales tipos de herramientas

Gestión de defectos

2.1. Herramientas de gestión de defectos

Permiten registrar, organizar y realizar un seguimiento de los errores encontrados durante el desarrollo y las pruebas del software.

Cuando un tester identifica un defecto, puede documentar su descripción, los pasos para reproducirlo, el resultado esperado, el resultado obtenido, la severidad, la prioridad y el estado de resolución.

De esta manera, el equipo puede conocer los problemas pendientes, asignar responsabilidades y comprobar si las correcciones realizadas funcionan correctamente.

Herramientas de ejemplo: Jira, Bugzilla y Azure DevOps.
Testing

2.2. Herramientas de pruebas de software

Permiten comprobar si el sistema cumple con los requisitos establecidos y detectar comportamientos incorrectos. Pueden utilizarse para realizar pruebas manuales o automatizadas.

Las pruebas automatizadas ejecutan instrucciones previamente definidas y comparan los resultados obtenidos con los esperados. Esto permite repetir pruebas con frecuencia y detectar errores después de modificar el código.

Herramientas de ejemplo: JUnit para pruebas unitarias en Java, Selenium y Cypress para automatizar pruebas web, y Postman para probar API.
Análisis estático

2.3. Herramientas de análisis de código

Examinan el código fuente sin necesidad de ejecutar el programa. Su objetivo es identificar posibles defectos, problemas de seguridad, incumplimientos de estándares y aspectos que dificulten el mantenimiento.

Pueden detectar código duplicado, estructuras complejas, variables que no se utilizan y determinados problemas de seguridad. Esto ayuda a encontrar fallos durante las primeras etapas del desarrollo.

Herramientas de ejemplo: ESLint y Pylint para aplicar reglas de estilo y detectar problemas, y SonarQube para análisis de calidad y seguridad.
Control de versiones

2.4. Herramientas de control de versiones

Permiten registrar los cambios realizados en el código fuente y mantener un historial de las modificaciones. Son fundamentales cuando varios desarrolladores trabajan sobre un mismo proyecto.

Facilitan la colaboración, la comparación de cambios, la recuperación de versiones anteriores y la identificación de modificaciones que pudieron introducir un defecto.

Herramientas de ejemplo: Git, GitHub, GitLab y Bitbucket.
Automatización

2.5. Herramientas de integración continua

Automatizan tareas que se ejecutan cuando se incorporan cambios al código fuente. Pueden compilar el proyecto, ejecutar pruebas automatizadas y realizar análisis estáticos.

Si alguna comprobación falla, el equipo recibe una notificación y puede corregir el problema antes de que avance hacia otras etapas del desarrollo.

Herramientas de ejemplo: Jenkins, GitHub Actions y GitLab CI/CD.
Rendimiento

2.6. Herramientas de pruebas de rendimiento

Evalúan cómo responde un sistema ante diferentes niveles de actividad y carga de trabajo. Se utilizan para medir tiempos de respuesta, solicitudes procesadas y uso de recursos.

Ayudan a identificar cuellos de botella y determinar si la infraestructura puede soportar la demanda prevista, especialmente cuando muchos usuarios acceden simultáneamente.

Herramientas de ejemplo: Apache JMeter, Gatling y k6.
Ciberseguridad

2.7. Herramientas de seguridad

Ayudan a identificar vulnerabilidades y riesgos que podrían comprometer la información o el funcionamiento del sistema.

Pueden analizar dependencias, revisar el código, detectar configuraciones inseguras y examinar aplicaciones en ejecución. Su objetivo es reducir la posibilidad de que un atacante aproveche fallos del sistema.

Herramientas de ejemplo: OWASP ZAP y Snyk.
Organización

2.8. Herramientas de documentación y gestión

Ayudan a organizar los requisitos, las tareas, los casos de prueba, las incidencias y la documentación del proyecto. Permiten que los integrantes del equipo compartan información y controlen el avance del trabajo.

Una documentación adecuada facilita la comprensión del sistema y permite que nuevos integrantes se incorporen al proyecto con mayor facilidad.

Herramientas de ejemplo: Confluence, Jira y Azure DevOps.

3. Importancia de las herramientas de calidad

La utilización de herramientas de calidad permite trabajar de forma más organizada, sistemática y eficiente. Entre sus principales beneficios se encuentran los siguientes:

Detección temprana

Ayudan a encontrar problemas antes de que lleguen a producción y afecten a los usuarios.

Reducción de costos

Detectar defectos durante el desarrollo suele ser menos costoso que corregirlos después de la implementación.

Automatización

Reducen el trabajo repetitivo y permiten ejecutar controles con mayor frecuencia.

Confiabilidad

Ayudan a comprobar que las funcionalidades continúen funcionando después de realizar cambios.

Mayor seguridad

Facilitan la identificación de vulnerabilidades y configuraciones incorrectas.

Trazabilidad

Permiten conocer qué se modificó, qué defectos se detectaron y qué pruebas se ejecutaron.

4. Ejemplo práctico de utilización

Supongamos que una empresa desarrolla una aplicación de comercio electrónico. Para controlar su calidad, el equipo puede utilizar diferentes herramientas durante el proyecto.

Cada herramienta cumple una función específica y se complementa con las demás para verificar que el producto funcione correctamente, sea seguro y responda a las necesidades de los usuarios.

  1. 01Git

    Administra los cambios del código fuente y permite recuperar versiones anteriores.

  2. 02SonarQube

    Analiza el código para identificar posibles defectos, vulnerabilidades y problemas de mantenibilidad.

  3. 03JUnit

    Comprueba que las funciones de cálculo de precios y otras operaciones produzcan resultados correctos.

  4. 04Postman

    Permite probar las API utilizadas para consultar productos y procesar pedidos.

  5. 05Selenium o Cypress

    Automatizan acciones de usuario, como iniciar sesión, agregar productos al carrito y finalizar una compra.

  6. 06JMeter o k6

    Evalúan el rendimiento cuando muchos usuarios realizan operaciones al mismo tiempo.

  7. 07Jira

    Registra los defectos encontrados, permite asignarlos y facilita el seguimiento de sus correcciones.

  8. 08Integración continua

    Ejecuta automáticamente las pruebas y los análisis cada vez que se incorporan cambios al proyecto.
